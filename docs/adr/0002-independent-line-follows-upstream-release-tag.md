# 独立版本线包跟随上游的发布专属 dist-tag

上游在 `dsh-v0.2.1-alpha.1`（2026-10-03）第一次让独立版本线包进入「稳定版是旧的、本次发布用预发布」的形态：`cordis`、`schemastery`、`cosmokit` 与四个 `cordis-plugin-*` 的 `latest` 全部停在上一版，而本次发布给它们各打了一个 `dsh-0-2-1-alpha-1` dist-tag 指向要用的版本。ADR 0001 的「按依赖方声明区间求解」在这种形态下不再足够，于是决定：**独立线选版优先采纳上游的发布专属 tag；没有该 tag 时退回 ADR 0001 的区间求解。同一个 tag 也决定闭包收集依赖边时读哪个版本的 manifest。**

## Considered Options

- **只做区间求解（ADR 0001 原样）**：真实 npm 安装确实只靠区间就能装出 `cordis@4.0.5-alpha.1`，但我们的区间是在 `latestStable` 那份 manifest 上收集的——独立线进入预发布形态后，那描述的是上一次发布的约束，会把两个不会同时存在的版本的声明混成一组（`["~4.0.5-alpha.1","~4.0.4"]`），于是模型判「永远无解」而 npm 装得好好的。
- **选版与收集边都改成定点迭代**：语义上等价于 npm 的递归解析，能根除这一类不一致，但改动落在闭包主循环上，且需要一个收敛上限与震荡检测。上游既然已经把答案打成 tag，读 tag 比重新推导更直接，也比推导更权威。
- **只把 tag 用于选版、不动收集边**：实测不成立——选版对了，纯度闸门仍拿过期区间复核真实安装，`@deepseek-ai/cordis@4.0.5-alpha.1（不满足声明区间 ~4.0.4）` 一类失败照旧，流水线依旧发不出去。收集边改由 ADR 0001 的定点迭代负责，本 ADR 因此退回它真正独有的部分：发布方意图。

## Consequences

- tag 指向的版本不在已发布列表里时响亮失败（registry 缓存滞后与上游漏发都属这一类），不静默退回区间解。
- tag 是上游本次发布新引入的做法，尚未观察到长期稳定性；一旦某次发布不再打 tag，选版自动退回 ADR 0001，探针日志里的 `chosenBy` 字段就是这两种来源的分界证据。
- 「独立版本线已与 npm 最新版分叉」那条每日预警在新形态下会天天命中（`latest` 本就该是旧的），它描述的仍是事实，但读的人要知道：跟随 tag 才是本意，最新版不是。

实测两点：把 fixture 里所有 `dist-tags` 抹掉、只靠定点迭代跑，5 轮收敛后独立线 9 个包与真实 npm 安装树逐包一致、零差异；tag 在位时 2 轮收敛。所以 tag 是加速器与「发布方指定」的凭据，不是正确性的唯一支点——这一点写在这里，免得后人以为删掉迭代也安全。
